# 数据库迁移

## 基线

`000001_init` 是 v1.3.0 之后合并出的基线，包含完整的表结构、索引与内置种子数据（管理员、角色、菜单、字典、参数、定时任务）。首次安装执行它即可得到可直接使用的数据库，不需要再按历史版本逐个升级。

该文件发布后视为冻结：**不要修改已发布的迁移**，任何结构调整都新增迁移文件。

## 新增迁移

- 下一个版本号从 `000002` 开始，文件名格式为 `NNNNNN_name.up.sql` / `NNNNNN_name.down.sql`。
- 下游项目建议业务迁移从 `001000` 开始，把 `000002`~`000999` 留给框架升级，避免撞号；详见 `docs/tool/upgrade.md`。
- `up` 与 `down` 必须成对存在。
- 迁移会在应用启动时由 golang-migrate 自动执行；单个文件可以包含多条语句（DSN 会自动追加 `multiStatements=true`）。
- 涉及种子数据的语句建议使用 `INSERT IGNORE` 或 `WHERE NOT EXISTS`，避免重复执行时报错。

## 从旧版本升级

迁移历史压缩后，v1.0.0 ~ v1.3.0 的数据库版本号（13 / 15 / 16）会高于当前内置基线（1）。应用启动时会拒绝执行并给出明确提示，按下面的方式处理：

- 已经是 **v1.3.0（schema version = 16）**：表结构与新基线完全一致。备份数据库后执行
  ```sql
  UPDATE schema_migrations SET version = 1, dirty = 0;
  ```
  再启动新版即可。
- **v1.0.0 ~ v1.2.0（schema version = 13 / 15）**：缺少 v1.3.0 的表结构，不能直接对齐版本号。请先升级到 v1.3.0 并完成迁移，再按上一条处理；或直接重建数据库（数据会清空）。
- 全新安装：保持空的 `schema_migrations` 即可，启动时会自动执行基线。
